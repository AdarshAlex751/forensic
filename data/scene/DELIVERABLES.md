## Part 2: spatial coverage tools

`backend/app/features/scene/devices.py` reads `data/scene/coverage.json`. The fixed public functions in `tools.py` remain `ap_covers(ap_id, room_id)` and `camera_sees(camera_id, room_id)`.

Each device record needs a `type` (`wifi_ap` or `camera`), `covered_rooms`, `excluded_rooms`, and a `source` documenting the measurement or approved scenario assumption. Explicit covered rooms return true; explicit excluded rooms return false. All other rooms raise `UnknownCoverageError` (a ValueError). Consumers should mark that check unavailable and continue other analysis; never interpret unknown as false. Conflicting records are rejected.

Coverage is spatial only. A camera's offline interval and an AP's connection history must be checked separately against evidence. Wi-Fi coverage does not prove that a person was in one particular room.

The checked-in coverage file deliberately contains no guessed coverage. Person 1 still needs to supply current-case AP IDs and the team must provide coverage decisions. The old devices.csv uses obsolete case IDs and must not be used to populate this file. cam-03's corridor location does not by itself establish whether the room interior is visible.

Validation: all 14 Python scene tests passed, including explicit positive/negative coverage, unknown rooms/devices, device-type mismatch, conflicting coverage, and missing-source behavior. The 74-second configured walking time is unchanged.
